# 配置项说明

管理器主要通过环境变量配置。Docker 部署写在 `docker-compose.yaml` 或 `docker run -e` 中，Windows 部署写在 `start_manager.bat` 中。

## 管理器变量

| 变量名 | 说明 | 默认值 |
| --- | --- | --- |
| `L4D2_MANAGER_PASSWORD` | Web 管理后台管理员密码。生产环境必须设置强密码。 | `laoyutangnb` |
| `L4D2_MANAGER_PORT` | 管理器监听端口。 | `27020` |
| `L4D2_GAME_PATH` | L4D2 的 `left4dead2` 游戏目录。 | `/left4dead2` |
| `L4D2_RCON_URL` | RCON 地址，格式为 `IP:端口` 或 `容器名:端口`。 | 空 |
| `L4D2_RCON_PASSWORD` | RCON 密码，需要和 `server.cfg` 一致。 | 空 |
| `L4D2_RESTART_BY_RCON` | 重启服务器时是否优先使用 RCON。推荐设为 `true`。 | `false` |
| `L4D2_RESTART_CMD` | 不使用 RCON 重启时执行的自定义命令。 | 空 |
| `L4D2_CONTAINER_NAME` | 未配置重启命令时用于重启的 Docker 容器名。 | `l4d2` |
| `L4D2_PLUGIN_STORE_PATH` | 插件库数据目录。 | `./plugins` |
| `STEAM_API_KEY` | 首页玩家列表中查询 Steam 账号的 L4D2 游戏时长。 | 空 |

## 游戏服镜像变量

| 变量名 | 说明 | 默认值 |
| --- | --- | --- |
| `L4D2_TICK` | 游戏服 Tickrate，支持 `30`、`60`、`100`、`128`。 | `30` |
| `L4D2_VAC` | 是否启用 VAC。`false` 会添加 `-insecure`。 | `false` |
| `L4D2_PORT` | 游戏服监听端口。 | `27015` |
| `L4D2_RCON_PASSWORD` | 写入游戏服 `server.cfg` 的 RCON 密码。 | `laoyutangnb!` |

## 数据目录

管理器默认把运行数据放在 `./data`，Docker 部署中通常映射为 `/data` 卷。该目录包含：

- `auth.db`：授权码记录、登录信息和自助领取冷却时间。
- `auth.key`：授权码指纹密钥，迁移时必须与 `auth.db` 一起保留。
- `manager_config.json`：自助授权、玩家统计、监控历史、地图精简、地图自动清理等设置。
- `access_control.json`：面板黑白名单和可信代理配置。
- `map_lifecycle.json`：正式地图的成功导入时间、锁定状态和文件版本信息。
- `map_lifecycle.initialized`：地图生命周期存储的初始化身份标记，需与状态文件一起保留。
- `map_lifecycle.journal.json`：地图文件变更的未完成操作记录，正常完成后清理；异常退出后用于恢复。
- `monitor.db`：性能监控历史数据。
- `player_stats.db`：玩家在线统计数据。
- `audit.db`：操作审计历史。

这些数据不属于游戏目录。迁移管理器时，如果希望保留统计、授权码状态、地图锁定和历史监控，请保留该目录；地图生命周期数据还需要与游戏地图目录、`addons/maplist.txt` 保持同一停写时间点，见[备份迁移流程](/operations/migration)。

### 地图自动清理设置

地图自动清理不使用环境变量。管理员在“系统管理 → 地图管理设置”开启，默认关闭，保留天数默认 3 天，可设置为 1–3650 的整数。关闭时保留已设置的天数。配置保存在 `manager_config.json` 的 `map_cleanup` 对象中：

```json
{
  "map_cleanup": {
    "enabled": false,
    "retention_days": 3
  }
}
```

其他面板配置字段保持不变，日常调整请使用设置页面。旧配置没有 `map_cleanup` 时按默认关闭、3 天加载。

清理根据 VPK 成功上传或下载导入的时间计算 `天数 × 24 小时`，不使用文件修改时间。仅处理 `addons/maplist.txt` 内有成功时间记录、已经过期且未锁定的 VPK；历史无时间的地图永不参与自动过期清理。关闭期间，新地图成功导入仍会记录时间。

每天按服务器本地时区 **03:00** 检查，设置页显示服务器时区和下次检查时间。开启或修改设置从下一计划周期生效，不立即清理；管理器重启同样从下一个 03:00 开始，不补跑停机期间错过的周期。成功时间使用 UTC 保存，服务器时区只决定每日计划，不改变保留时长。采用夏令时的服务器每天按当地 03:00 重新计算计划，不以固定 24 小时间隔代替每日计划。

锁定与解锁仅管理员可操作。单删、多选、清空和自动清理均由后端保留锁定 VPK；普通临时授权用户已有的地图删除权限不因此扩大或缩小。功能不检查运行中地图、待办队列或包依赖，需要保留的 VPK 请分别锁定。详细行为见[地图管理](/features/maps#地图自动清理)。

### 操作审计保留期限

`audit.db` 中的操作审计固定保留最近 30 天，不提供环境变量或面板配置项。管理器启动后异步检查一次，此后从本次启动起每 24 小时检查一次；不是每天零点执行，重启会重新计时。

清理依据操作开始时记录的 Unix 秒时间戳，删除严格早于“检查时刻减去 30 × 24 小时”的记录，恰好位于边界上的记录保留。计算不受服务器时区或夏令时影响。两次检查之间，刚超过 30 天的记录会暂时保留到下次检查；停机期间不执行，恢复启动后补查。

清理与异步审计写入共用工作协程，每批最多删除 1000 条，批间继续处理待写记录，避免两个任务争用 SQLite 写锁。单批清理设置 5 秒超时；数据库错误会记录到管理器运行日志，本次停止清理，下一次每日检查再重试。启动时数据库不可用则不启动审计写入和清理任务，恢复后需重启管理器。任务随管理器进程退出而结束。

该规则只影响操作审计，不影响 SourceMod 日志文件、容器运行日志、性能监控或玩家统计的保留策略。删除授权码本身不会级联删除审计历史，审计历史仍按上述 30 天规则清理。

## 权限模式

后台有三类登录身份：

| 身份 | 来源 | 权限 |
| --- | --- | --- |
| 管理员 | `L4D2_MANAGER_PASSWORD` | 可进行上传、删除、启停、保存配置、生成授权码等写操作。 |
| 访客 | 临时授权码或自助授权码 | 以查看为主，部分敏感页面和写操作会被隐藏或禁用。 |
| 地图上传者 | 管理员生成的“仅地图上传与下载”授权码 | 可分片上传地图、查询和取消自己的上传，添加下载任务并解析链接，查看、取消、重试和清理自己的下载任务，以及执行地图热重载。 |

授权码由管理员在“授权码管理”中创建，默认随机 32 位，也可自定义 8–32 位，并选择普通临时权限或仅地图上传与下载。所有记录都可修改到期时间、撤销或删除，也可一键清理过期记录。自助授权需要管理员在该页面先开启，访客按全局冷却限制领取短期访问码，始终使用普通临时权限。详情见[授权码管理](/features/auth-codes)。

原 JWT 授权码在升级后全部失效，需要重新创建。管理员密码继续有效；旧 `private.key` 文件不再用于认证。

## 面板访问控制

面板访问控制不使用环境变量，仅管理员可以在“访问控制”页面配置。页面包含“面板黑白名单”“可信代理”和“游戏黑名单”三个 Tab：前两个分别保存并立即生效，游戏黑名单通过 RCON 实时读取和修改游戏服务端原生封禁。

面板规则支持地区关键字、单 IP 和 CIDR；地区规则依赖后端随包提供的 `ip2region_*.xdb` 数据文件。首次没有页面配置时，面板黑白名单默认关闭，可信代理默认为 `127.0.0.0/8` 和 `::1/128`。

可信代理决定管理器是否接受 `X-Forwarded-For` 和 `X-Real-IP`。只应填写自己实际控制、会直接连接管理器的反向代理地址；配置不正确会导致管理器把代理地址当作客户端地址。完整的启用步骤、判断顺序和反向代理配置见[面板访问控制](/features/access-control)。
