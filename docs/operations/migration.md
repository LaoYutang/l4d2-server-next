# 备份迁移流程

迁移服务器时建议同时导出“备份文件”和“插件文件”。备份文件保存配置状态，插件文件保存插件资源，两者配套使用最稳妥。

## 旧服务器导出

1. 进入“备份管理”，点击“新建备份”，输入容易识别的名称，例如 `迁移前备份`。
2. 在备份列表中点击单个备份的“导出”，下载该备份的 `.yaml` 文件。
3. 如果要一次导出全部备份，点击“全部导出”，下载 `backups_all.yaml`。
4. 进入“插件管理”，点击“导出所有插件”，等待压缩完成后下载 `plugins_all.zip`。

导出插件时会占用服务器 CPU 和带宽，建议避开游戏高峰期。

## 新服务器导入

1. 部署并启动新服务器和管理器。
2. 确认 `L4D2_GAME_PATH`、`L4D2_RCON_URL`、`L4D2_RCON_PASSWORD` 等配置正确。
3. 进入新服务器“插件管理”，上传旧服务器导出的 `plugins_all.zip`。
4. 进入“备份管理”，点击“导入”，选择旧服务器导出的 `.yaml` 或 `backups_all.yaml`。
5. 如果导入的备份名称已存在，系统会自动追加 `(1)`、`(2)` 等后缀。
6. 在备份列表中选择目标备份，点击“还原”。
7. 还原完成后重启 L4D2 服务器。

## 迁移范围

备份文件包含：

- 启用插件列表。
- 插件配置修改。
- 管理员列表。
- 服务器信息。
- 服务器配置。

备份文件不包含：

- 地图文件。
- 地图上传时间、锁定记录和自动清理设置。
- 插件文件本身。
- 完整游戏目录。
- 监控数据库。
- 玩家统计数据库。
- 授权数据库 `auth.db` 和授权指纹密钥 `auth.key`。
- 操作审计数据库 `audit.db`。

地图和完整游戏目录请按实际部署方式单独复制或重新安装。

### 地图与生命周期状态

迁移地图并保留锁定及成功导入时间时：

1. 在旧面板关闭地图自动清理，等待正在执行的地图变更结束。若提示未完成操作或恢复失败，先在原游戏路径修复并完成恢复，不要直接换路径迁移未完成的事务。
2. 停止旧、新管理器，配套复制游戏地图目录、`addons/maplist.txt` 和管理器整个 `data/` 目录，避免文件与记录来自不同时间点。复制时保留地图文件修改时间。
3. 配套保留 `map_lifecycle.json`、`map_lifecycle.initialized` 及可能存在的 `map_lifecycle.journal.json`；不要通过删除初始化标记绕过状态错误。未完成操作日志包含原路径，跨路径恢复会被拒绝。
4. 启动新管理器后核对地图列表、锁定状态、自动清理开关、服务器时区和下次检查时间，再按需启用自动清理。

只复制 VPK 或只恢复管理器数据，不能视为完整的地图状态恢复。文件内容或修改时间与生命周期记录不符时，会跳过自动清理，不会据此自动解除原锁定。没有成功时间记录的历史地图仍保持未知，不会通过文件修改时间补齐或自动过期清理。

需要保留授权记录、冷却和统计历史时，停机复制管理器整个 `data/` 目录；`auth.db` 与 `auth.key` 必须配套迁移。旧 JWT 授权码在升级后全部失效，无需迁移旧 `private.key`，请重新发放授权码。
